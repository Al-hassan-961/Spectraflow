# Spectraflow production dependencies
# ==================================
#
# Design rule: NumPy is the ONLY hard runtime dependency. Every DSP stage
# (phase sanitization, clutter rejection, Butterworth filtering, STFT and the
# spectral confidence metric) has a complete pure-NumPy implementation, so the
# full pipeline runs with nothing else installed. The packages below are
# accelerators and optional transports that are detected at import time; the
# pipeline degrades gracefully when they are missing rather than failing.

# --- required ---------------------------------------------------------------
numpy>=1.22
uvicorn>=0.20            # pure-ASGI server; serves both app flavours

# --- optional: native acceleration -----------------------------------------
# Builds core/ into the `spectraflow_core` extension, which accelerates the
# hot DSP primitives. Requires a C++17 compiler. Without it the NumPy path is
# used and results are numerically identical.
pybind11>=2.10

# --- optional: real neural pose inference ----------------------------------
# When absent (or when no model file is configured) spectraflow falls back to
# its deterministic, CSI-driven analytic pose estimator.
#
# NOTE: there is no official onnxruntime wheel for Android/aarch64, which is
# the reference Termux deployment, so the analytic estimator is the expected
# path there.  Install with:  pip install onnxruntime
onnxruntime>=1.16

# --- optional: FastAPI flavour of the server -------------------------------
# Spectraflow serves a dependency-free ASGI application by default, with
# identical routes and payloads. FastAPI requires pydantic-core, whose Rust
# build fails on Android/aarch64 (no prebuilt wheel), so on Termux the
# dependency-free application is what runs. Nothing else changes.
#
# Install with:  pip install fastapi
fastapi>=0.100

# --- optional: SciPy --------------------------------------------------------
# Not used by the pipeline itself (the Butterworth design and IIR filtering are
# implemented directly, in both C++ and NumPy, so results are reproducible
# across backends). Listed only for downstream analysis and comparison work.
# On Termux, scipy frequently fails to build for Android's Python.
# scipy>=1.9

# --- development ------------------------------------------------------------
pytest>=7.0
